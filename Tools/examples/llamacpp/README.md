# Своя модель на llama.cpp за полчаса

Пример от начала до конца: поднять `llama-server`, объяснить игре, как до него дойти, и
убедиться, что она действительно дошла. Ничего из этого не требует пересборки форка и не
оставляет следов в git.

Файлы каталога:

| файл | куда | зачем |
|---|---|---|
| `llama-server.sh` | куда угодно | запуск модели; разобраны флаги, которые агент замечает |
| `10-endpoints.yml` | `ai_data/config.d/` | профиль провайдера: адрес, диалект, окно, таймаут |
| `20-modes.yml` | `ai_data/config.d/` | свой режим на этой модели и свой секретный пул |
| `server_config.toml` | `config.toml` инстанса | рубильники: цепочка, бюджет хода, число агентов |

---

## 1. Поднять модель

```bash
cp Tools/examples/llamacpp/llama-server.sh ~/llama-agent.sh
chmod +x ~/llama-agent.sh
MODEL=~/models/ваша-модель.gguf ~/llama-agent.sh
```

Три флага, без которых агент не заработает или заработает вдвое хуже, — они разобраны в самом
скрипте: `--jinja` (без вызова инструментов у агента нет вообще никаких действий),
`--parallel` (один слот на агента, иначе они вытесняют префикс-кэш друг друга) и `--alias`
(имя модели обязано совпасть с полем `model` в профиле).

Проверка до всякой игры:

```bash
curl -s --noproxy '*' 127.0.0.1:8080/v1/models | jq -r '.data[].id'
curl -s --noproxy '*' 127.0.0.1:8080/props | jq '.default_generation_settings.n_ctx'
```

`--noproxy '*'` здесь не для красоты. Если машина экспортирует `HTTP_PROXY`/`ALL_PROXY`
глобально, запрос на loopback уходит в прокси и **зависает** — не отваливается с ошибкой, а
именно зависает до таймаута. Ровно то же случится с игровым сервером, если в профиле не стоит
`proxy: None`.

## 2. Объяснить игре, где модель

```bash
mkdir -p ai_data/config.d
cp Tools/examples/llamacpp/10-endpoints.yml ai_data/config.d/
cp Tools/examples/llamacpp/20-modes.yml     ai_data/config.d/   # по желанию
```

Почему в `ai_data/`, а не в `Resources/Prototypes/`: `Content.Server/Acz/ContentMagicAczProvider.cs`
раздаёт всю папку `Resources/` каждому подключившемуся игроку. Настройка сервера, положенная
туда, уезжает в клиент — а ключ уехал бы к первому же зашедшему. `ai_data/` в `.gitignore`, не
раздаётся и уже содержит ключи, память и файлы личности.

Порядок чтения — по имени файла. Нумеруйте: два файла могут трогать один прототип, и побеждает
последний.

## 3. Включить

В `config.toml` инстанса — ключи из `server_config.toml` этого каталога. Главные три:

```toml
[ai]
enabled = true
llm_chain = "llamacpp"
llm_total_timeout = 660   # больше, чем timeoutSeconds профиля
```

Затем в консоли сервера:

```
aiagent config reload
```

## 4. Убедиться, что дошли

```
aiagent config          # какие файлы прочитаны и что они переопределили
aiagent llm probe       # НАСТОЯЩИЙ поход к модели теми же полями, какими ходит агент
aiagent mode            # во что разрешились режимы — с учётом накладки
```

`probe` существует потому, что настройка эндпоинта ломается **тихо**. Ни одна из пяти обычных
поломок не даёт ошибки при старте:

* модель называется не так, как в `/v1/models` — 404 на каждом ходу;
* `ctxLimit` завышен против настоящего `n_ctx` — отказ по переполнению посреди раунда;
* `compactHigh` не меньше окна — свёртка не срабатывает никогда;
* `reportsCache: true` у провайдера, который про кэш не сообщает — тревога «префикс-кэш сломан»
  на каждом ходу, и настоящая поломка в этом шуме теряется;
* `timeoutSeconds` не меньше `ai.llm_total_timeout` — **фаллбек не пробуется вовсе**; это видно
  только в тот вечер, когда голова цепочки ляжет.

`probe` сверяет заявленное в профиле с тем, что провайдер делает на самом деле, и печатает
расхождения. Ходит он через тот же прокси, с тем же ключом и тем же диалектом, что боевой ход —
проверка, идущая другим путём, проверяет не то, что играет.

Это настоящее обращение к модели: у платного профиля — токены, у подписки — доля окна. Один
запрос на профиль, но нулём это не назвать.
