# Публикация сервера

Что уже сделано и что осталось сделать руками.

## Как SS14 подключает игрока

Это надо понимать, иначе схема с обратным прокси выглядит рабочей, а не работает:

1. Лаунчер идёт по `ss14s://ss14.vnaa.ru` за **HTTP-статусом** — обычный TCP, HTTPS.
2. Из ответа он берёт `connect_address` и подключается к нему по **UDP**, через Lidgren.

Формулировка самого RobustToolbox не оставляет места для толкования (`Robust.Shared/CVars.cs`):

> `status.connectaddress` — *UDP address that should be advertised and the launcher will use to connect to.*

### Про Nginx Proxy Manager

У NPM есть вкладка **Streams** поверх модуля `stream` nginx, и она **умеет UDP**, а не только
HTTP — так что шаг 2 через NPM провести можно. Контейнер здесь работает в режиме сети `host`,
то есть слушать UDP на хосте ему ничто не мешает.

Но NPM стоит **за тем же роутером**, что и всё остальное. Он раздаёт только то, что роутер до
машины донёс, и создать входящую связность не может.

**Замерено, а не предположено.** Через SOCKS5 UDP ASSOCIATE (пакет уходит из сети удалённого
прокси, то есть снаружи) при слушающем сокете на этой машине:

```
UDP 1212  — не дошёл
UDP 443   — не дошёл
UDP 27015 — не дошёл
```

Роутер не пропускает UDP ни на одном из проверенных портов. Правило на роутере обязательно.

После того как правило появится, NPM Stream имеет смысл ровно в одном случае: если хочется
принимать на другом внешнем порту и отображать его на 1212. Если роутер форвардит UDP 1212
напрямую на машину, NPM в этой цепочке — лишний хоп.

⚠️ Учтите конфликт портов: NPM в host-режиме и сам SS14 слушают на одном хосте. Стрим на 1212
столкнётся с сервером — принимайте на другом порту (например UDP 443) и форвардите на 1212.

### Если роутер настроить нельзя

Игровой UDP тогда придётся заводить снаружи:

- UDP-релей на VPS (`socat UDP4-LISTEN:1212,fork UDP4:<домашний-ip>:1212` — работает, только если
  домашний адрес достижим, то есть это не решение при NAT);
- туннель с поддержкой UDP: playit.gg, ngrok (платный тариф) — они дают публичный UDP-эндпоинт,
  который и надо прописать в `status.connectaddress`;
- Tailscale для закрытого круга: подключение по `100.125.32.120:1212` без единого проброса.

## Осталось сделать руками

### 1. Роутер 192.168.31.1 — проброс UDP (обязательно)

```
UDP 1212 -> 192.168.31.250:1212
```

Замерено, что сейчас этого нет: запрос снаружи (через удалённый прокси) на
`http://213.5.31.34:1212/status` не отвечает, тогда как `https://vnaa.ru/` отвечает —
проброшены только 80 и 443.

### 2. Nginx Proxy Manager — хост для статуса

Proxy Hosts:

```
Domain:      ss14.vnaa.ru
Scheme:      http
Forward to:  192.168.31.250 : 1212
SSL:         Let's Encrypt, Force SSL
Websockets:  не нужны
```

Streams — только если принимаете игровой UDP на порту, отличном от 1212:

```
Incoming port:  443        (или любой другой, проброшенный роутером по UDP)
Forward host:   192.168.31.250
Forward port:   1212
UDP:            да
TCP:            нет
```

и тогда в конфиге `status.connectaddress = "udp://ss14.vnaa.ru:443"`.

Проверка после настройки:

```bash
curl -s https://ss14.vnaa.ru/status
```

Должен вернуться JSON с именем сервера.

### 3. Проверка снаружи

```bash
# HTTP-статус через прокси
curl -s https://ss14.vnaa.ru/status

# UDP-порт — с ЧУЖОЙ машины, не с этой:
nc -zuv ss14.vnaa.ru 1212
```

Потом подключиться лаунчером по `ss14s://ss14.vnaa.ru`.

## Если решите публиковать в хабе

`advertise = true` включает публикацию в браузере серверов и вместе с ней обязанности из
[правил хаба](https://docs.spacestation14.com/en/community/space-wizards-hub-rules.html):

- **Контакты обязательны.** Дословно: *«If we are unable to contact you we may be forced to go
  immediately to delisting»*. Нужен Discord или сайт в `[infolinks]`.
- Имя и описание чистые, без рекламы в имени (правило 3.1).
- Модерация: жалобы разбираются, страйки живут год, три страйка — постоянный делистинг.

**Ботов и ИИ-игроков правила не запрещают** — я прочитал все три секции, такого правила нет.
Правило 1.7 про ложную информацию хабу касается счётчика игроков и региона, а наш агент —
серверный NPC и в счётчик не попадает вовсе.

## Что стоит проверить до публики

- **Фаза 6 не пройдена.** Суточного прогона не было. Известно, что агент открывает двери и
  отказывается убивать, но не известно, что с ним через шесть часов и десяток компакций.
- **llama-swap делится с mcbot.** Один слот, `-np 1`. Если Aero заработает одновременно, они
  начнут выбивать друг другу префикс-кэш, и замедлятся оба. Либо не запускать одновременно,
  либо поднять `-np 2` и пинить `id_slot` на каждого агента.
