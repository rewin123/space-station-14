# Отладчик ИИ станции

Веб-страница поверх шины событий агента: разговор, память, скиллы, собранный промпт, статистика и
отправка сообщений агенту.

## Запуск

На сервере (`bin/Content.Server/server_config.toml`, секция `[ai]`):

```toml
debug_enabled = true
debug_bind = "127.0.0.1:9080"
debug_token = "..."   # ASCII, иначе сервер откажется биндиться
debug_ring = 512
```

Здесь:

```sh
npm install
npm run dev      # http://localhost:5173
```

Вставить адрес и токен в шапке — они сохранятся в localStorage.

Прокси в dev-сервере намеренно нет: любое реальное развёртывание этой страницы — статика на
чужом origin, так что кросс-ориджинный путь проверяется на каждом сохранении, а не однажды в
проде.

## Развёрнуто

https://aidebug.vnaa.ru — за basic-auth, логин/пароль в `/home/rewin/aidebug-serve/basic-auth.txt`.

Обновить страницу после правок:

```sh
/home/rewin/aidebug-serve/deploy.sh
```

Устройство:

```
браузер → NPM :443 (basic-auth, Let's Encrypt) → 127.0.0.1:9081 (контейнер aidebug)
                                                   ├── /      → собранная страница
                                                   └── /api/  → 127.0.0.1:9080 + Bearer-токен
```

Порт 9080 наружу не смотрит — только 127.0.0.1, а NPM сидит на host-network и достаёт его оттуда.
Токен подставляет вспомогательный nginx, страница его не знает; поэтому в развёрнутом виде поле
токена можно оставить пустым, а `baseUrl` сам подставится как `/api`.

Отдельный слой nginx нужен потому, что NPM в каждом своём location ставит
`proxy_set_header Authorization ""` — так устроен его Access List, — и вписать туда Bearer значит
драться с шаблоном при каждом обновлении NPM.

**Host для /api подставляется жёстко** (`127.0.0.1:9080`), а не пробрасывается. `HttpListener`
сопоставляет запрос со своим префиксом по этому заголовку и на чужой отвечает
`Not Found (Not Found)` — выглядит как неправильный путь, а на деле неправильный заголовок.

## Мультисессионность (19.08.2026)

Агентов на сервере до четырёх: ядро (`core`) и три киборга. Отладчик показывает всех.

Разделение проходит по естественному шву — тому же, по которому уже разделены кадры на шине:

| ресурс | маршрут | вес |
|---|---|---|
| процессное (память, скиллы, заметки) + ростер | `GET /state` | десятки-сотни КБ, одно на всех |
| один агент (промпт, вся переписка, статистика) | `GET /session?agent=<id>` | мегабайты, по требованию |
| ростер | едет в `/state`, `/health` и `/events` | сотни байт, всегда |

Истории всех агентов сразу **не качаются**: сеется только выбранный, остальные — лениво, при
переключении. Четыре переписки по сотне тысяч токенов в одной вкладке — это десятки мегабайт строк.

Три вещи, о которые здесь легко споткнуться:

- **`/session` на неизвестного агента отвечает 200 с `agent: null`, а не 404.** Агент мог уйти
  между кадром `session.started` и запросом. 404 у клиента терминален (`ApiError.terminal`) и
  навсегда останавливает петлю опроса — то есть «правильный» код погасил бы отладчик из-за
  штатной гонки.
- **`/events` не фильтруется по агенту и параметров не принимает.** Курсор один на процесс,
  клиент разбирает ленту сам по полю `session`. Две ленты с двумя курсорами дали бы четыре режима
  рассинхрона вместо одного.
- **Ростер в ответе `/events` — не кадр.** К нему не относятся ни курсор, ни resync; снимается он
  в момент возврата долгого опроса и может отставать на все 25 секунд. Сеять агента по ростеру
  нельзя — только по `session.started` или по выбору оператора.

Правило досева (`src/stream/seedgate.ts`): снимок на `seq = S` ставит курсор ЭТОГО слайса в `S`,
дальше применяются кадры с `seq > S`, а накопленное за время полёта снимка доигрывается по
возрастанию. Строго `>`, а не `>=`: сервер читает `bus.Seq` первым, поэтому кое-что с `seq > S`
могло попасть и в снимок — дубль ловится проверкой `body_epoch`/`index` и даёт пересев одного
агента. Буфер, а не остановка петли: снимок может вернуться на `S` меньшем текущего курсора, и
кадры из промежутка иначе потерялись бы молча.

Пересев теперь **поагентный**. Раньше любое расхождение роняло всю ленту; при четырёх агентах и
вчетверо более частых компакциях это означало бы отладчик, который непрерывно моргает. Заодно
`prefix.replaced` больше не требует снимка — payload несёт всё, что нужно.

## Тесты

```sh
npm test         # apply, seedgate, demux, pairing, series, memoryBlock
npm run build    # vue-tsc + vite
```

`seedgate.spec.ts` — правило досева, включая главный кейс «снимок отстал от курсора».
`demux.spec.ts` — настоящая петля с подменёнными запросами: кадры двух агентов не смешиваются,
процессные доезжают до всех, пересев одного не двигает общий курсор.

Тесты `apply.spec.ts` — это тесты машины состояний: пропущенное и задвоенное сообщение, смена
эпохи тела, окно зомби после конца сессии, идемпотентность повторного применения. Их стоит гонять
перед любой правкой `src/stream/`.

## Грабли, которые уже наступлены

**`.npmrc` с `include=dev` нужен.** На этой машине `NODE_ENV=production` выставлен глобально, и npm
читает это как «не ставить devDependencies». Обычный `npm install` тогда ставит vue, но молча
пропускает vite, и первым признаком становится `vite: not found`, похожее на сломанный локфайл.

**Таймаут запроса не опускать ниже 25 секунд.** Сервер держит долгий опрос ровно столько, и
оборванный запрос НЕ освобождает серверный слот: роутер получает токен остановки сервера, а не
запроса. Тринадцать брошенных опросов кладут отладочный эндпоинт целиком.

**Петля опроса — модульный синглтон.** Не переносить в `onMounted`: HMR даст вторую петлю с тем же
курсором, и каждое сообщение отрисуется дважды.
