# skill_start — стартовая библиотека скиллов агента

Справочник по игре, с которого начинает свежий агент: 166 статей плюс один скилл, написанный
самим агентом в бою (`restore-core-power`).

Рядом лежит второй слой — `wiki_skills/`, 60 статей, снятых с внутренней вики игры. Вместе они
одна библиотека, и разделены по происхождению: здесь то, что вычитано человеком, там то, что
перенесено из вики моделью и принято линтером. Подробности — `wiki_skills/README.md`.

## Зачем отдельная папка

Рабочая библиотека живёт в `ai_data/skills/`, а `ai_data/` целиком в `.gitignore` — там же лежат
ключ к API, токен отладчика, логи и `CREW.md` с именами живых игроков. Версионировать этот
каталог нельзя.

Но сам справочник версионировать нужно: он вычитан, сверен с первоисточником и стоил дорого.
Поэтому здесь лежит его снимок, а `ai_data/skills/` остаётся рабочей копией, которую куратор
правит каждую смену. Расхождение между папками — это ровно то, чему агент научился сам.

## Как раскатить

```sh
mkdir -p ai_data/skills
cp skill_start/*.md wiki_skills/*.md ai_data/skills/
```

**Поверх наработанного не копировать.** Агент дописывает статьи сам через `skill_edit`, и
расхождение папок — это ровно его опыт за смены. Перед раскаткой сравни (`diff -rq skill_start
ai_data/skills`) и сначала перенеси расхождения сюда, в снимок: `ai_data/` целиком в `.gitignore`,
и всё, что осталось только там, теряется без следа при любом сбросе.

Файл `README.md` копировать не нужно и не вредно: `SkillStore.Parse` отбрасывает всё, что не
начинается с `# имя` и строки `когда:`, и просто пишет предупреждение в лог.

Перезаписывать рабочую библиотеку поверх наработанного не стоит без причины — обратно из неё
ничего не восстановить.

## Формат и проверка

Одна статья — один файл `<имя>.md`:

```
# имя-статьи
когда: когда её открывать, не длиннее 60 символов
тело, не длиннее 4800 символов
```

Строка `когда` — единственное, что попадает в системный промпт агента; тело он открывает по
требованию через `skill_view`. Отсюда правило: статей должно быть немного, а тела могут быть
большими. Ссылка `[[имя-другой-статьи]]` в тексте — приглашение открыть её тем же `skill_view`.

Перед коммитом правок:

```sh
python3 Tools/wiki/lint.py
```

Он вызывает `Tools/check_skills.py` по ОБЪЕДИНЕНИЮ обеих папок, и только так и надо: хабы
`справочник-*` ссылаются на статьи из `wiki_skills/`, поэтому по одному снимку прогон покажет
десятки ссылок в никуда, которых на самом деле нет.

Линтер повторяет разбор `SkillStore.Parse` и валит прогон на файле, который парсер молча
выбросит, на слишком длинном `когда`, на теле свыше кодового потолка в 5000 символов и на ссылке
в никуда. Тело между 4800 и 5000 — предупреждение «тесно»: статья ещё работает, но запаса на
дописку у агента уже нет, и делить её надвое лучше до того, как он упрётся.
